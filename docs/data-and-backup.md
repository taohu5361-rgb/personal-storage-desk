# 数据与备份

个人收纳台的 SQLite 数据库保存工作空间、分类、资产记录、文字、提示词、备注、布局、设置和文件路径。它不把所有材料打包进数据库。

## 托管与引用

托管导入将原文件复制到配置的托管目录；引用导入记录源路径。封面及样图也有自己的路径和保存方式，不应仅按资产主文件模式判断所有附属文件在哪里。移动、删除或失去访问权限都会影响本地文件读取。

修改托管目录设置只影响配置，不会自动移动或迁移之前保存的文件。迁移时先备份，确认旧文件与数据库记录的对应关系，再验证所有主文件、封面、样图与字体仍能打开；目前没有一键完整迁移保证。

删除记录与删除文件是不同操作。资产或工作空间删除界面提供相应的托管文件处理选项；引用源文件应保留。涉及真实材料时，应先备份并仔细确认界面选项，避免把记录删除当作可随时恢复的整理操作。

## 数据库备份与恢复

设置中的数据库备份生成 SQLite 记录备份，**不包含原文件、封面 / 样图文件或字体文件**。完整备份需要同时保存数据库、托管材料、引用源文件与实际使用的字体，并保持可恢复的路径关系。

恢复会检查所选数据库完整性，并在覆盖当前数据库前保存一份 `before-restore.sqlite3` 记录副本。该副本也不包含材料文件，不能代替完整备份。恢复记录后仍需检查缺失引用、图片、字体和布局；源文件已经删除时，恢复数据库不会把它找回来。

离线复制运行目录前先正常关闭程序，不要只复制仍在使用的 SQLite 主文件而忽略 WAL / SHM 状态。优先使用应用内备份功能取得一致的数据库记录副本。备份可能包含私人文件路径与文本，请自行保管，不要提交到公开仓库。

## 兼容与测试隔离

内部应用标识与数据库文件名保留历史值。显示名称变更不会隔离数据；同一 Windows 用户下的历史版本和本项目可能使用同一应用数据位置。

独立测试使用 debug 构建与绝对路径的 `CREATIVE_CLOTH_TEST_DATA_DIR`，详见开发说明。该变量在 release 中无效。公开源码不包含任何真实数据库、托管材料、私人字体或用户备份。
